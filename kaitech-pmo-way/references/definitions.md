# Glosarium & Definisi Metrik

| Istilah | Definisi Kaitech |
|---|---|
| Baseline | Versi rencana (scope, jadwal, effort, milestone) yang disetujui di G2. Bernomor v1.0; re-baseline → v2.0 hanya via CR/Steerco. |
| Forecast | Perkiraan terkini tanggal selesai. Boleh berubah tiap minggu; selisih ke baseline = varian. |
| Bobot | Kontribusi deliverable terhadap progress total. Σ bobot = 100%. Ditetapkan saat baseline. |
| Progress bukti | Nilai 0/25/50/75/100% berdasarkan level bukti (skill `evidence-progress`). |
| Planned % | Persentase yang seharusnya tercapai pada tanggal status menurut baseline (linear antara tanggal mulai–selesai baseline per deliverable). |
| Earned % | Σ (bobot × progress bukti). |
| SPI | Earned % ÷ Planned %. ≥ 1 = sesuai atau lebih cepat. |
| Varian jadwal | Hari kerja antara forecast dan baseline selesai. Positif = terlambat. |
| Health Score | Skor 0–100 gabungan 5 dimensi (skill `health-score`). |
| Eksepsi | Kondisi yang melewati toleransi; wajib dilaporkan ke level di atas. |
| Pending klien | Item yang menunggu tindakan klien (data, approval, akses, kehadiran). Dicatat sebagai Action Item pihak Klien dan, bila memengaruhi jadwal, sebagai Dependency. |
| BAST | Berita Acara Serah Terima; bukti penerimaan deliverable dan dasar penagihan. |
| Billing gate | Syarat penagihan termin: milestone Tercapai + BAST ditandatangani + dokumen pendukung lengkap. |
| Umur | Hari kerja sejak item dibuka sampai tanggal status (atau ditutup). |
| Watermelon reporting | Laporan hijau padahal kondisi dasar kuning/merah. Dilarang. |
